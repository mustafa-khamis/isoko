How null/unlimited values are handled:
If `max_active_listings` or `max_listings_per_period` or `max_sponsored_ads_per_period` are null, the `buildPlanFeatures` utility explicitly returns "Unlimited active listings", "Unlimited listings", or "Unlimited sponsored ads" respectively.

How zero values are handled:
If `max_sponsored_ads_per_period` is exactly 0, the utility returns "No sponsored ads included".

How singular/plural labels are handled:
If a value equals 1, the utility formats the label as singular ("active listing", "sponsored ad"). If > 1, it formats as plural.

Exact Current Plan root cause: 
When a user clicked "Select plan", the backend `subscribe` method inserted a new `user_subscriptions` row with `status = 'pending'`. The backend `getCurrentSellingPlan` query specifically filtered for `status = 'active'`, so the new subscription was completely ignored. Additionally, the old active subscription was never cancelled, causing the query to fallback to the existing 'active' Trader Plus subscription (since it picks the active subscription with the highest priority).

Authoritative current-plan source: 
The backend `user.selling_plan` (derived securely from the `user_subscriptions` table via `getCurrentSellingPlan` and sent in the `/users/me` endpoint).
